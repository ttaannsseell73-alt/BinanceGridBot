# State Machine

Order lifecycle management is strictly deterministic. The state machine operates on the `IntentJournal` and ensures every transition is valid.

## Lifecycle States

1. **INIT**: The order intent has been generated by the StrategyEngine and risk has been reserved by RiskGuard. It is saved in the database but no network call has been made yet.
2. **SUBMIT_UNKNOWN**: The network request (`POST`) has fired. We do not know if the exchange received it.
3. **ACKNOWLEDGED**: The exchange returned a successful HTTP 200 response or a WS `NEW` event was received. The exchange has accepted the order.
4. **PARTIALLY_FILLED**: The exchange reported that part of the order was filled.
5. **FILLED**: The exchange reported that the entire order quantity was filled. Risk is permanently realized.
6. **CANCEL_PENDING**: A cancel request (`DELETE`) has been fired.
7. **CANCELED**: The exchange confirmed the order is canceled. Reserved risk is freed.
8. **CONFIRMED_REJECTED**: The exchange deterministically rejected the order during submission. Reserved risk is freed.
9. **UNKNOWN**: The reconciler detected that an `ACKNOWLEDGED` order is missing from the exchange entirely. This is a critical error state.

## State Transitions

- `INIT` -> `SUBMIT_UNKNOWN` (ExecutionEngine fires network call)
- `SUBMIT_UNKNOWN` -> `ACKNOWLEDGED` (REST HTTP 200 or WS `NEW`)
- `SUBMIT_UNKNOWN` -> `CONFIRMED_REJECTED` (REST HTTP 400 error codes)
- `SUBMIT_UNKNOWN` -> `FILLED` (WS `FILLED` arrived before REST response)
- `ACKNOWLEDGED` -> `PARTIALLY_FILLED` (WS `TRADE`)
- `PARTIALLY_FILLED` -> `FILLED` (WS `TRADE` with 0 remaining quantity)
- `ACKNOWLEDGED` / `PARTIALLY_FILLED` -> `CANCEL_PENDING` (ExecutionEngine fires cancel)
- `CANCEL_PENDING` -> `CANCELED` (WS `CANCELED` or REST HTTP 200)

Invalid state transitions (e.g., `FILLED` -> `CANCELED`) are strictly prevented by the `IntentJournal`.
